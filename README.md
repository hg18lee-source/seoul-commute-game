# 대중교통 출근 게임


## 온라인 본편과 관리자 시연

Node.js 22, npm, PostgreSQL 서버 도구, `pg_config`, WebGL 2 브라우저가 필요합니다. Ubuntu에서 PostgreSQL 도구가 없으면 `sudo apt install postgresql libpq-dev`로 준비합니다.

```bash
cd "$(git rev-parse --show-toplevel)"
if [ -s "${NVM_DIR:-$HOME/.nvm}/nvm.sh" ]; then
  source "${NVM_DIR:-$HOME/.nvm}/nvm.sh"
  nvm use 22
fi
bash tutorial/run-local.sh --admin 개발관리자
```

1. 터미널에서 개발용 관리자 비밀번호를 정합니다. 서로 다른 문자가 8개 이상 들어간 20~128자 비밀번호가 필요합니다.
2. [관리자 로그인](http://127.0.0.1:8034/?admin=1)에서 로그인해 [관리자 대시보드](http://127.0.0.1:8034/administrator)의 오늘 집계를 봅니다.
3. 별도 브라우저 프로필에서 [본편](http://127.0.0.1:8034/)을 열고 개발용 ID를 생성합니다. 지하철 또는 버스 코스를 시작해 회사까지 완주합니다.
4. 관리자 **운영 요약**에서 완주 건수와 최단 시간이 바뀌고, 최근 실행이 **기록 저장으로 자동 실행**으로 표시되는지 확인합니다. 서버는 저장 후 자동 집계하고, 화면은 보이는 동안 5초마다 현재 완주 현황을 조회합니다.
5. **집계 기준·근거 보기**에서 서울 기준일과 코스별 공식 버전을 확인합니다. 완주 행의 플레이 ID를 실행 이력의 **ID·집계 내용 보기**에 표시된 플레이 ID와 대조합니다.
6. **운영 요약 → 지금 다시 집계**를 눌러 **관리자가 재계산**과 **변경 없음**을 확인합니다. 집계 사이에 새 공식 완주가 저장되면 결과가 달라질 수 있습니다.
7. **요청 이력**에서 작업을 **완주 기록 제출**로 좁힙니다. **상세 보기 → 요청 ID 복사**로 자동 집계 실행의 요청 ID와 대조합니다. **API 사용 현황**과 **요청 이력**은 같은 필터를 사용하며 **현재 페이지 새로고침**으로 최신 결과를 가져옵니다.

터미널에서 `Ctrl+C`를 누르면 로컬 서버와 임시 DB가 종료됩니다. 로컬 실행기는 새 임시 DB를 사용하며 종료 시 개발 계정과 기록을 정리합니다. 격리 DB 테스트는 루트에서 `bash tutorial/run-local.sh --test`로 실행합니다. 별도 성공 조건은 [검증 기록](report.md)에 있습니다.

## 이전 정적 시안

공덕동 집에서 시청역 인근 회사까지 플레이하는 로우폴리 3D 웹 시안입니다. 가입 없이 Play로 시작합니다.

- 방향키 이동, Shift 달리기, M 스마트폰, Enter 안내 시작, E 상호작용, Space 손잡이, Esc 일시정지.
- 지하철은 공덕에서 5호선을 타고 애오개를 지나 충정로에서 2호선으로 갈아탑니다. 승강장 문이 열렸을 때 좌우 방향키로 타고, 차 안에서 앞쪽 문을 향해 걸어 내립니다.
- 7016번은 공덕역1번출구에서 타고 북창동·소공동주민센터건너에서 내립니다. 서울역버스환승센터를 떠난 뒤 벨을 누르고 뒷문에서 E를 누르세요.
- 배차와 이동은 시안의 고정 스케줄입니다. 시간 배율은 6배, 시작 체력은 100이고 회복은 없습니다. 이동이 느리다는 플레이 피드백에 따라 걷기 3.6m/s, 달리기 5.4m/s로 조정했습니다. 달리기 체력 소모는 현실 초당 0.2, 정차 시간은 기존 설정을 유지합니다. 이전 속도의 로컬 최고 기록은 삭제하지 않고 별도 키에 보관하며, 새 속도의 최고 기록은 분리합니다.
- 임시 설정은 배차·역간 시간, 건물·통로 배치, 약식 도보·도착 예상 시간, 45·115·195초의 해프닝 시점, 4초 대응 시간 및 0.1초 기록 반올림입니다. 도보 거리는 대표 동선에서 약 60m를 목표로 구성했습니다. 체력 30 및 평균 7분의 밸런스 조정은 남아 있습니다.
- 운행은 두 경로의 인접 역·정류장 일부를 포함한 축소 구간입니다. 실시간 배차, 전체 24개 조합, 일일·랜덤 경쟁, 서버 인증·랭킹은 시안 범위 밖입니다. 시연용 닉네임과 기록은 브라우저별로 보관됩니다.
- 장면과 인물은 자체 제작 지오메트리를 사용했습니다. Three.js 라이선스는 dist/vendor/THREE-LICENSE.txt에 포함되어 있습니다.
- 버스 정류장 순서는 서울특별시 노선정보조회 서비스의 7016번 응답을 기준으로 정리했습니다. [공공데이터포털](https://www.data.go.kr/data/15000193/openapi.do)

로컬에서 실행하려면 프로젝트 폴더에서 `python3 -m http.server --directory dist 8000`을 실행하고 브라우저에서 `http://localhost:8000`을 엽니다. WebGL 2가 필요합니다. 교통 데이터 버튼은 Sites 서버에서 실행됩니다. 정적 로컬 실행에서도 기존 게임을 플레이할 수 있습니다.

## 교통 데이터 확인

공개 메인 화면의 버튼이 같은 출처의 `/api/transit`에 요청합니다. 5분 성공 캐시, 30초 실패 캐시를 적용하며 실제 조회 시각을 유지합니다. 조회에 실패한 데이터는 성공한 데이터와 별도로 표시합니다. 조회 결과는 게임 운행 자료와 독립적입니다.

Sites 서버에는 `SEOUL_OPENAPI_KEY`와 `DATA_GO_KR_SERVICE_KEY`를 비밀 환경변수로 설정합니다. 배포 전에 `python3 worker/build.py`로 Worker를 생성합니다.

## GitHub Pages 공개

게임의 정적 파일은 GitHub Pages에도 게시할 수 있습니다. 프로젝트 사이트 주소는 `https://<GitHub ID>.github.io/<저장소 이름>/` 형식입니다.

- `dist/`의 HTML, CSS, JS와 `vendor/`만 게시합니다. `dist/server/`, `.env`, API 인증키, Sites 저장소 자격 증명은 게시하지 않습니다.
- GitHub Pages에서는 교통 데이터 확인 요청을 기존 공개 Sites 서버의 `/api/transit`으로 보냅니다. 서버가 공개 데이터 응답에 CORS 헤더를 제공하며, 인증키는 계속 Sites 서버에 보관합니다.
- Sites 서버 변경도 배포되어야 GitHub Pages의 교통 데이터 조회가 작동합니다. 게임 플레이 자체는 정적 파일로 실행됩니다.
- 기본 상대 경로를 사용하므로 저장소 하위 경로에서도 게임 자산을 불러올 수 있습니다.

## 주말 개발 인수인계 브랜치

기존 GitHub Pages의 루트 파일은 그대로 두고, 온라인 본편을 `online-game/`, 프로토타입·그래픽 검토 자료를 `prototype/`, 배포 확인 자료를 `evidence/`에 보관하는 구조입니다. 개발 환경, DB 분리, 자산 출처, 제외한 원본은 [HANDOFF.md](HANDOFF.md)와 [ASSET_TRANSFER.md](ASSET_TRANSFER.md)를 확인하세요. 온라인 앱을 실행하려면 `cd online-game && npm ci && npm run build && npm run dev`를 사용합니다.
