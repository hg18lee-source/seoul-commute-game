# 대중교통 출근 게임

이 작업 브랜치는 Vercel용 공식 계정과 기록을 제공합니다. [온라인 운영 문서](ONLINE.md)에 실행·마이그레이션·운영 방법이 있습니다. 플레이 가능한 공식 경로는 완주 검증을 우선한 공덕 → 충정로 지하철·도보 코스 하나입니다.

공덕동 집에서 시청역 인근 회사까지 플레이하는 로우폴리 3D 웹 시안입니다. 가입 없이 Play로 시작합니다.

- 방향키 이동, Shift 달리기, M 스마트폰, Enter 안내 시작, E 상호작용, Space 손잡이, Esc 일시정지.
- 공덕역으로 들어가 개찰구를 지난 뒤 5호선 오른쪽 승강장에서 충정로 방면 열차를 타세요. 테스트용 역 간 이동은 12초이며, 충정로역에서 내려 출구로 나와 회사 포털까지 걸으면 완주합니다.
- 배차와 이동은 시안의 고정 스케줄입니다. 시간 배율은 6배, 시작 체력은 100이고 회복은 없습니다. 이동이 느리다는 플레이 피드백에 따라 걷기 3.6m/s, 달리기 5.4m/s로 조정했습니다. 달리기 체력 소모는 현실 초당 0.2, 정차 시간은 기존 설정을 유지합니다. 이전 속도의 로컬 최고 기록은 삭제하지 않고 별도 키에 보관하며, 새 속도의 최고 기록은 분리합니다.
- 임시 설정은 배차·역간 시간, 건물·통로 배치, 약식 도보·도착 예상 시간, 45·115·195초의 해프닝 시점, 4초 대응 시간 및 0.1초 기록 반올림입니다. 도보 거리는 대표 동선에서 약 60m를 목표로 구성했습니다. 체력 30 및 평균 7분의 밸런스 조정은 남아 있습니다.
- 운행은 두 경로의 인접 역·정류장 일부를 포함한 축소 구간입니다. 실시간 배차, 전체 24개 조합, 일일·랜덤 경쟁, 서버 인증·랭킹은 시안 범위 밖입니다. 시연용 닉네임과 기록은 브라우저별로 보관됩니다.
- 장면과 인물은 자체 제작 지오메트리를 사용했습니다. Three.js 라이선스는 dist/vendor/THREE-LICENSE.txt에 포함되어 있습니다.
- 버스 정류장 순서는 서울특별시 노선정보조회 서비스의 7016번 응답을 기준으로 정리했습니다. [공공데이터포털](https://www.data.go.kr/data/15000193/openapi.do)

로컬에서 실행하려면 프로젝트 폴더에서 `python3 -m http.server --directory dist 8000`을 실행하고 브라우저에서 `http://localhost:8000`을 엽니다. WebGL 2가 필요합니다. 교통 데이터 버튼은 Sites 서버에서 실행됩니다. 정적 로컬 실행에서도 기존 게임을 플레이할 수 있습니다.

## 교통 데이터 확인

공개 메인 화면의 버튼이 같은 출처의 `/api/transit`에 요청합니다. 5분 성공 캐시, 30초 실패 캐시를 적용하며 실제 조회 시각을 유지합니다. 조회에 실패한 데이터는 성공한 데이터와 별도로 표시합니다. 조회 결과는 게임 운행 자료와 독립적입니다.

Sites 서버에는 `SEOUL_OPENAPI_KEY`와 `DATA_GO_KR_SERVICE_KEY`를 비밀 환경변수로 설정합니다. 배포 전에 `python3 worker/build.py`로 Worker를 생성합니다.

## GitHub Pages 공개

게임의 정적 파일은 GitHub Pages에도 게시할 수 있습니다. 프로젝트 사이트 주소는 `https://<GitHub ID>.github.io/<저장소 이름>/` 형식입니다.

- `dist/`의 HTML, CSS, JS와 `vendor/`만 게시합니다. `dist/server/`, `.env`, API 인증키, Sites 저장소 자격 증명은 게시하지 않습니다.
- GitHub Pages에서는 교통 데이터 확인 요청을 기존 공개 Sites 서버의 `/api/transit`으로 보냅니다. 서버가 공개 데이터 응답에 CORS 헤더를 제공하며, 인증키는 계속 Sites 서버에 보관합니다.
- Sites 서버 변경도 배포되어야 GitHub Pages의 교통 데이터 조회가 작동합니다. 게임 플레이 자체는 정적 파일로 실행됩니다.
- 기본 상대 경로를 사용하므로 저장소 하위 경로에서도 게임 자산을 불러올 수 있습니다.

## 경로 수정과 자동 자체 점검

경로 ID, 출발역, 도착역, 노선, 방향, 역 간 이동 시간은 `dist/journey.js` 한 곳에서 정의하며 브라우저와 서버 검증이 같은 정의를 가져옵니다. `npm run dev`와 `npm run build`는 먼저 DB 연결 없이 실제 서버 경로 규칙에 완주 시나리오를 넣어 점검합니다. 자체 점검은 `npm run test:journey`로 따로 실행할 수 있습니다. 온라인 로그인과 기록 저장에는 별도 로컬 PostgreSQL과 `.env.local` 설정이 필요합니다.
