# 공덕 출근길 · 4차 거리 검토

게임 원본 폴더에서 다음 명령을 실행합니다.

```sh
python3 -B street-realism-v4-review/serve.py 8000
```

브라우저에서 `http://127.0.0.1:8000/street-realism-v4-review/index.html`을 엽니다. 검토 서버는 루프백에만 바인딩하며 검토 페이지, 지정한 참고 사진 및 공유 렌더링 자산만 제공합니다.

- 사진 구도에서는 참고 사진과 실시간 렌더가 나란히 표시됩니다.
- 3인칭 이동을 누른 뒤 **←**로 골목을 나와, 큰길에서 **↑**로 역 입구 쪽으로 이동합니다. Shift로 달릴 수 있습니다. 차도와 계단 안쪽은 관찰 범위입니다.
- 측면, 반대 방향, 골목, 가로수, 보도, 상점 및 역 입구를 각각 볼 수 있습니다. 경량 모드는 픽셀 비율·그림자 맵 외에도 수목, 배선과 일부 보행자 지오메트리를 줄입니다.

사진은 별개의 장소를 보여줍니다. 전체 레이아웃에는 street-main.png만 우선 사용했습니다. 눈높이 1.64m, 수직 화각 53°, 보도 폭 약 8.8m, 차도 폭 약 17m, 골목 폭 약 6.1m, 연석 높이 약 0.15m는 검토용 추정치입니다. 촬영 좌표·실측 치수·가려진 면과 실제 역 입구 형태는 확인하지 않았습니다. 공덕역 5·6호선 및 1번 출구 표기는 [고용노동부 서울서부지청 안내](https://moel.go.kr/local/seoulseobu/introduce/direction/list.do)를 참고했습니다. 역의 배치와 구조는 사진을 참고한 검토용 설계입니다. 야간 사진의 조명은 사용하지 않았습니다.

## 소스·사용 자료

- `scene.js`는 3차 자체 제작 장면에서 파생한 4차 모델과 절차형 재질의 원본입니다. 페이지를 열면 같은 시드로 생성합니다.
- `review.js`는 4차 관찰 카메라, 구역·충돌 경계, 조작 및 품질 설정입니다. 본편의 48° 고정 방향과 기존 3.6/5.4m/s를 읽기 전용으로 재사용했습니다. 골목 벽이 카메라를 가리면 거리만 줄입니다.
- `index.html`, `review.css`, `serve.py`는 독립 검토 화면과 로컬 서버입니다. `captures/`는 브라우저 캡처입니다.
- 거리 지오메트리, 절차형 색·범프 맵, 가상 간판은 자체 제작했습니다. 외부 모델이나 유료 자산은 없습니다. 공유하는 Three.js r180·GLTFLoader는 기존 [MIT 라이선스](../dist/vendor/THREE-LICENSE.txt)를 따릅니다. 기존 주인공 GLB·모션과 3차 파일은 수정하지 않았습니다.
- 참고 사진은 `references/`의 비교 자료이며 텍스처나 메시로 사용하지 않았습니다. 인물·워터마크·번호판 이미지를 모델에 복사하지 않았습니다. 공개 배포용 패키지는 만들지 않았으며 향후 패키징 범위에도 참고 사진 디렉터리를 포함하지 않습니다.

## 남은 차이

사진과 비교하면 먼 건물의 입면, 상가 내부, 수목의 가는 가지·잎 밀도, 유리의 복합 반사, 자동차와 인물의 실루엣이 단순합니다. 보행자는 소수의 정지 배치입니다. 다음 개선 우선순위는 거리별 쇼윈도·벽 상세를 줄이는 LOD, 정적 반사와 근경 수목의 밀도 조정, 실제 하드웨어 GPU에서의 프레임 측정입니다.

## 동일 조건 브라우저 비교

Edge 147 WebGL 2에서 1280×800 브라우저 뷰포트를 사용했습니다. 3차와 4차 모두 큰길의 같은 월드 위치 `(3.54,0,8)`, 48° 카메라 및 같은 출력 버퍼 크기로 맞췄습니다. 정지 장면을 16프레임 예열 후 약 3.2초씩 두 번 렌더링했습니다. 프레임 간격은 rAF 기준이며 고정 구도 결과입니다.

| Edge 렌더러 | 품질 / 출력 | 3차 중앙값 · p95 범위 | 4차 중앙값 · p95 범위 |
|---|---|---|---|
| Microsoft Basic Render Driver D3D11 | 상세 / 1213×560 | 50.0ms · 50.1–66.7ms | 33.3ms · 50.0ms |
| Microsoft Basic Render Driver D3D11 | 경량 / 1031×476 | 33.3ms · 33.4–50.0ms | 16.8ms · 33.4ms |
| SwiftShader Vulkan | 상세 / 1213×560 | 249.9–250.0ms · 250.1–265.6ms | 187.5–203.1ms · 218.7–234.3ms |
| SwiftShader Vulkan | 경량 / 1031×476 | 187.5–203.1ms · 203.1–203.2ms | 140.7–156.2ms · 156.3ms |

| 같은 큰길 화면 | 3차 상세 / 경량 | 4차 상세 / 경량 |
|---|---|---|
| 드로 콜 | 475 / 475 | 267 / 254 |
| 렌더링 삼각형 | 78,513 / 78,513 | 72,403 / 56,708 |
| 장면 재질 | 78 / 78 | 71 / 71 |
| Three.js 텍스처 객체 | 113 / 113 | 67 / 67 |
| 초기 비압축 로드 | 약 2.90MB | 약 2.91MB |

초기 비압축 로드는 약 0.54MB의 비교 사진을 포함합니다. 4차의 사진 제외 로드는 약 2.37MB입니다. Three.js 텍스처 객체 수에는 그림자 및 내부 렌더 타깃 등이 포함되며 실제 VRAM 바이트를 뜻하지 않습니다. Microsoft Basic Render Driver와 SwiftShader는 모두 소프트웨어 렌더링입니다. 실제 하드웨어 GPU, GPU 프레임 시간, VRAM은 미측정입니다. Basic 경량은 동일 시작 구도의 중앙값과 p95가 각각 16.8ms와 33.4ms였으나, 모든 프레임의 30FPS 및 전체 동선의 안정적인 30FPS는 입증되지 않았습니다. SwiftShader는 두 모드에서 모두 목표를 충족하지 못했습니다. 현재 의심되는 비용은 5만–7만 삼각형, 근경 유리·재질 픽셀 처리와 소프트웨어 래스터라이저입니다. GPU 타이머로 병목을 분리하지는 않았습니다.

Windows Edge에서 포트 8000 주소를 열었고 9개 화면 모드, 대각선 정규화, 걷기와 달리기, 골목 출구, 역 앞 계단 경계, 포커스 이탈 후 입력 해제, 고정 카메라 방향을 검증했습니다. 역 내부는 관찰 범위 밖입니다.
