# 공덕동 출발 거리 검토

게임 원본 폴더에서 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

- 비교 화면은 `http://127.0.0.1:8000/street-review/street-preview.html`입니다. 기존/개선 버튼으로 같은 카메라에서 전환합니다. 관찰 버튼은 전체·외관·역·정류장 구도를 선택합니다. 직접 걸어보기 버튼을 누르면 방향키와 Shift를 사용할 수 있습니다.
- 본편은 `http://127.0.0.1:8000/dist/`입니다. Play로 시작하세요. M은 스마트폰, Esc는 일시정지, E는 역 입구와 버스 승차 상호작용입니다.
- `screenshots/before-*.png`는 변경 전 Edge 기준 캡처입니다. `screenshots/after-*.png`는 동일한 카메라 위치·시야각·조명으로 찍은 개선본입니다.

## 모델과 배치

`dist/gongdeok-street.js`가 재생성 가능한 원본입니다. 공덕마루 공동 현관, 모퉁이 커피, 새참 편의점, 아침결 빵집, 공덕 새길빌딩의 외벽을 재사용 가능한 창·문·틀·지붕·차양으로 조립했습니다. 쇼윈도에는 제한된 진열 깊이를 넣었습니다. 모델·간판·보도 텍스처는 모두 자체 제작했으며 외부 에셋은 사용하지 않았습니다. Three.js는 프로젝트에 포함된 MIT 라이선스의 r180을 사용합니다.

층위별 입면, 보도 줄눈·경계석·점자블록, 나무 보호틀, 정류장 지붕·유리·벤치와 역 난간·계단을 추가했습니다. 벽·기둥·화단 등은 플레이 경계 밖으로 빼고, 차양은 캐릭터 높이보다 위에 배치했습니다. 지하철 입구는 5호선, 정류장은 7016번으로 표시합니다. 계단은 입구의 시각적 깊이를 보여주며, 역 진입은 기존 E 상호작용을 사용합니다.

기존 출발 좌표 `(-5,15)`, 역 상호작용 `(-5,-24)`, 버스 상호작용 `(7,-42)`, 이동 경계, 카메라와 3.6/5.4m/s 속도를 유지했습니다. 기존 외부 구간의 길이를 바꾸어 기획서의 약 60m 목표를 다시 맞추지는 않았습니다. 정류장에 보이는 버스 차체만 측면으로 0.44m 옮겨 기둥과 간격을 냈습니다. 버스 모델·운행과 E 판정은 기존과 같습니다. 조명·안개·노출 설정은 동일합니다. 멀리 보이는 입면은 간략화했고, NPC 및 버스 외형은 기존 모델입니다.

## 성능 측정

Edge 147, WebGL 2, SwiftShader, 1280×720, 동일한 출발 구도에서 25회 예열 후 버전당 약 3.2초씩 두 번 측정했습니다. 측정 순서는 기존·개선·개선·기존입니다.

| 지표 | 기존 | 개선 |
|---|---:|---:|
| 장면 그리기 요청 | 617 | 344 |
| 렌더링 삼각형 | 12,123 | 33,329 |
| 장면에서 참조한 재질 | 71 | 149 |
| 장면에서 참조한 텍스처 | 11 | 11 |
| 프레임 간격 중앙값 | 93.7ms | 140.6ms |
| 프레임 간격 p95, 두 번의 범위 | 109.4–125.0ms | 140.7–156.2ms |
| 렌더 제출 시간 중앙값, 두 번의 범위 | 6.4–6.7ms | 4.2–4.7ms |

형상 배열과 인스턴스 행렬의 추정 합계는 1,096,842 → 765,002바이트이고, 맵의 RGBA + 밉맵 추정 합계는 11,141,120 → 7,943,509바이트입니다. 실제 VRAM, 하드웨어 GPU 시간 및 실제 기기 FPS는 미측정입니다. 소프트웨어 환경에서는 프레임 간격이 악화되어 저사양 성능 검토가 남아 있습니다.
