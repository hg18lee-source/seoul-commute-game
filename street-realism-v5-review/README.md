# 공덕 출근길 · 5차 거리 검토

게임 원본 폴더에서 `python3 -B street-realism-v5-review/serve.py 8001`을 실행합니다.
브라우저에서 `http://127.0.0.1:8001/street-realism-v5-review/index.html`을 엽니다.

- **3인칭 이동**에서는 방향키와 Shift를 사용합니다. ↑로 골목을 나와 큰길로 진행합니다. 골목과 큰길이 연결되는 부분에서만 카메라가 부드럽게 방향을 바꾸고, 각 구역에서는 캐릭터가 회전해도 추적 각도가 유지됩니다.
- 공덕역 입구 중앙에서 ↑로 내려가면 하부 조명 통로에 도달합니다. 끝 벽에서 멈추며 ↓로 올라올 수 있습니다. 역 승강장과 차도는 이동 범위 밖입니다.
- **상점 글자 가리기**로 상점 간판·메뉴·부착물의 글자를 숨기고 업종별 배치를 비교할 수 있습니다.
- **상세/경량** 품질의 해상도, 그림자 맵과 잎 메시 상세도, 일부 장식·보행자 가시성이 다릅니다. 검토용 충돌은 플레이어의 환경 경계에 적용하며 NPC 간 충돌은 구현하지 않았습니다.

## 변경 파일과 제작

- `details.js`는 분식점의 식탁·의자·카운터·천막, 안경점의 분리된 쇼윈도·선반·안경테, 석재·벽돌의 색/범프/거칠기 맵, 수피와 잎 알파 텍스처를 생성합니다.
- `scene.js`는 4차의 큰길 구도를 이어받아 위 자산을 연결하고 입구의 13단과 석재 벽·손잡이·조명 통로를 구성합니다.
- `review.js`는 4차의 추적·입력을 확장합니다. 본편의 걷기 3.6m/s와 달리기 5.4m/s를 공유하고, 높이 및 계단 양발 보정은 검토 전용입니다. 정지, 휴대폰 보기, 보행 한 프레임의 세 가지 정지 자세를 사용합니다.
- `index.html`, `review.css`, `serve.py`는 독립 검토 화면 및 루프백 서버입니다. `captures/`의 v4/v5 쌍은 같은 구도입니다. 제작 자산은 브라우저에서 고정 시드로 재생성됩니다.

전체 배치는 street-main.png를 우선했습니다. sidewalk의 줄눈·연석, commercial-street의 층별 외장 구분, storefront의 유리문과 천막, station-entrance의 캐노피·기둥 구조, residential-alley의 골목·배선을 각 부분에만 참고했습니다. 사진별 장소는 서로 다릅니다. 크기와 가려진 부분은 추정이며, 실제 공덕역 1번 출구의 실측 복원은 아닙니다. 야간 참고 사진의 조명은 사용하지 않았습니다.

거리·가구·안경테·절차형 텍스처와 가상 간판은 자체 제작했습니다. 외부 모델, 유료 자산, 사진 텍스처를 사용하지 않았습니다. 공유하는 Three.js r180·GLTFLoader는 기존 [MIT 라이선스](../dist/vendor/THREE-LICENSE.txt)를 따릅니다. 제공 사진은 로컬 비교 이미지로만 참조하며 공개 패키지는 만들지 않았습니다. 본편과 4차의 코드·자산에는 쓰지 않았습니다.

## 남은 그래픽 차이

두 상점은 보도에서 보이는 쪽만 제작했습니다. 안경 선반과 식당 가구는 업종을 알아볼 수 있게 구성했지만 표면 마감과 가구의 세부는 여전히 단순합니다. 유리에는 환경맵과 시선 각도에 따른 반사가 적용되며 주변 물체의 실시간 거울상은 없습니다. 잎은 알파 컷아웃 카드여서 매우 가까이 보면 평면이 보입니다. 계단 높이 보정은 단별 접촉을 위한 근사이며, 빠른 달리기의 모든 발 위치나 캐릭터 충돌 형태를 실측 검증하지는 않았습니다. 원경과 인물 모델은 4차에서 이어받았습니다.

## 같은 조건의 4·5차 성능

Edge 147, WebGL 2, 브라우저 1280×800, 큰길의 동일 월드 좌표와 48° 카메라 구도. 품질마다 출력 해상도를 맞추고 16프레임 예열 후 약 3.2초씩 두 차례 측정했습니다. 아래는 rAF 프레임 간격이며 렌더 구간은 정지 카메라입니다.

| 렌더러 / 품질 | 출력 해상도 | 4차 중앙값 / p95 | 5차 중앙값 / p95 |
|---|---|---|---|
| Basic Render Driver D3D11 / 상세 | 1213×560 | 33.3–33.4 / 50.0ms | 49.9–50.0 / 50.1ms |
| Basic Render Driver D3D11 / 경량 | 1031×476 | 16.8–33.2 / 33.4ms | 33.3 / 33.4ms |
| SwiftShader Vulkan / 상세 | 1213×560 | 203.1–218.7 / 218.8–234.4ms | 250.0 / 265.6–328.0ms |
| SwiftShader Vulkan / 경량 | 1031×476 | 156.2–156.3 / 171.9ms | 171.8–171.9 / 171.9–234.3ms |

| 같은 큰길 화면 | 4차 상세 / 경량 | 5차 상세 / 경량 |
|---|---|---|
| 드로 콜 | 267 / 254 | 290 / 277 |
| 렌더링 삼각형 | 72,403 / 56,708 | 57,969 / 52,284 |
| 장면 재질 | 71 | 88 |
| Three.js 텍스처 객체 | 67 | 78 |
| 초기 비압축 로드 | 약 2.91MB | 약 2.93MB |

초기 로드량은 약 0.54MB의 로컬 비교 사진을 포함합니다. Three.js 텍스처 객체에는 내부 렌더 타깃 등이 포함되며 VRAM 용량을 나타내지 않습니다. 두 장치는 모두 소프트웨어 렌더링이며, 하드웨어 GPU, GPU 시간, 실제 VRAM, 동선 전체 프레임 시간은 미측정입니다.

최적화 전 5차의 SwiftShader 상세 중앙값은 281.3–312.5ms, 경량은 203.2–234.4ms였습니다. 먼 안경테 LOD, 경량 외벽의 범프/거칠기 연산 생략, 잎 카드 밀도 조절로 비용을 줄였습니다. 최종 5차도 4차보다 느렸습니다. 재질·드로 콜 증가와 반투명 유리·알파 컷아웃 픽셀 처리 비용이 후보이며 GPU 타이머로 비중을 분리하지는 않았습니다.

## 검증

Windows Edge에서 포트 8001 로딩을 확인했습니다. 4차·5차의 사진, 상점, 나무 및 역 구도를 같은 위치·방향과 화각으로 캡처했고, 분식점과 안경점을 글자 없이도 따로 캡처했습니다. 방향키와 Shift, 대각선 속도 정규화, 골목에서 큰길 전환, 계단 하강과 상승, 약 -1.438m 하부 바닥 도달, 통로 끝의 충돌, 포커스 이탈 뒤 수평 이동 정지를 확인했습니다. `captures/v5-play.webm`은 브라우저에서 실제 조작한 이동 녹화입니다.
