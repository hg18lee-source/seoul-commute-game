프로젝트 루트에서 `python3 -B subway-entrance-review/serve.py 8002`를 실행한 뒤 [게임 시안](http://127.0.0.1:8002/subway-entrance-review/index.html)을 엽니다. [원본 GLB 검사](http://127.0.0.1:8002/subway-entrance-review/inspect.html)와 [기존 5차](http://127.0.0.1:8002/street-realism-v5-review/index.html)도 같은 서버에서 열립니다. WebGL 2가 필요합니다.

기본 화면은 골목에서 시작합니다. 화면에 포커스를 둔 상태로 ↑를 눌러 큰길로 나온 뒤 계속 북쪽으로 진행하세요. 입구 앞에서 좌우 키로 한쪽 계단에 줄을 맞추고 ↑로 내려갑니다. 지하 통로 끝에서 ↓로 돌아올 수 있습니다. Shift는 달리기입니다. 고정 카메라의 방향은 골목 접점에서만 전환되고 입구에 가까워지면 캐릭터를 더 가까이 따라갑니다.

## 배치와 구현

- 0.86 균일 배율을 사용했습니다. 입구 기둥은 최고 약 3.05m, 앞쪽 계단 전체 폭은 약 3.90m, 에스컬레이터 한 줄의 단 폭은 약 1.37m입니다. 손잡이는 앞쪽 최고점에서 보도 기준 약 1.06m이고 앞단에서 서면 약 0.72m입니다. 약 1.8m인 주인공을 기준으로 크기를 맞췄습니다. 측면 화면에도 같은 크기의 보행자가 서 있습니다. 상점 쪽 구조물 사이의 정적 간격은 약 1.55m입니다.
- 보도 높이에서 앞계단이 시작합니다. 계단 개구부만 잘라 석판 보도를 잇고 지하 바닥은 약 −4.05m에 맞췄습니다. 원래 표지판을 제거하고 입구에 공덕역·1번 출구·5·6호선 표기를 넣었습니다. 유리에 구워진 가상 역명 두 곳은 해당 아틀라스 픽셀을 보정했습니다.
- 0.29m 반경을 적용한 외곽·중앙·양쪽 난간과 끝 벽 경계로 이동을 제한합니다. 점프 없는 이동에서 지붕에 닿을 수 있는 상판 경로는 열리지 않습니다. 단차 높이는 측정한 상단 단과 에스컬레이터 단의 높이 구간으로 계산하고, 캐릭터 몸체를 보간하며 발 목표 높이를 단별로 보정합니다. 에스컬레이터는 정지 상태입니다.
- 아침 하늘과 노출, 방향광을 5차에서 공유합니다. 메탈릭, 거칠기, 노멀, 발광 아틀라스를 유지했습니다. 베이스 컬러·발광은 sRGB, 표면 데이터는 비색상으로 읽으며 GLTFLoader의 `flipY=false`와 원본 tangent를 사용합니다. 유리는 알파 블렌딩하고, 석재·금속은 깊이 기록과 그림자를 사용합니다. 지하 바닥의 과한 반사를 줄이기 위해 금속성 계수를 조정했습니다.
- [최적화본](assets/entrance.glb)은 1,971,884바이트, 메시 19개, 삼각형 4,896개입니다. 주변 지면·단말기·볼라드·표지와 해당 버퍼 및 아틀라스를 제거하고 입구의 1,024px 지도 4장을 유지했습니다. 원본 대비 76.9% 작습니다. 코덱 압축은 적용하지 않았습니다. `python3 -B subway-entrance-review/prepare_model.py`로 재생성합니다.

전송량은 Resource Timing의 `transferSize` 합계이며 주 문서와 비교 사진을 제외합니다. 응답 본문 합계는 2.386 → 4.355MB입니다. 드로 콜·삼각형은 Three.js의 동일 프레임 렌더 카운터입니다. 수집된 초기 리소스 응답은 모두 HTTP 200이었습니다. 하드웨어 GPU, GPU 시간, VRAM, 전체 플레이 동선 프레임 간격은 미측정입니다.

## 플레이 검증과 남은 범위

Edge에서 키 입력을 보내 골목에서 큰길로 나온 뒤 오른쪽 계단으로 내려갔습니다. 바깥쪽 및 중앙 난간에 좌우 키를 계속 눌렀을 때 각 경계에서 이동이 멈췄습니다. 지하 끝 벽에서 Y −4.048m에 정착했고, 통로에서 왼쪽 계단으로 옮겨 보도까지 올라왔습니다. 키를 떼거나 캔버스 포커스를 잃었을 때 수평 위치가 고정됐습니다. 검토한 계단과 지하 통로 화면에서 카메라가 주인공 전신을 담았습니다. 최종 재시험에 자산 로딩 실패와 브라우저 오류가 기록되지 않았습니다.
