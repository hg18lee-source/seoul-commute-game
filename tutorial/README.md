## 로컬 실행과 종료

일반 WSL에서 Node.js 22.x, npm, PostgreSQL 서버 도구와 WebGL 2 브라우저를 준비합니다. 아래 명령은 필요한 npm 의존성을 설치하고 개발 서버를 시작합니다.

```bash
cd '/mnt/c/Users/통신운용/Desktop/AWS프로젝트/seoul-commute-tutorial-integrated'
nvm use 22
bash tutorial/run-local.sh
```

[로컬 메인](http://127.0.0.1:8034/)의 비로그인 화면에서 **AI 출근 튜토리얼**을 누르거나 [튜토리얼](http://127.0.0.1:8034/tutorial/)을 엽니다. 서버는 127.0.0.1에 바인딩합니다. 종료와 재시작은 Ctrl+C를 누른 후 같은 실행 명령을 사용하세요.

각 실행은 임시 PostgreSQL에 개발 계정과 기록을 보관합니다. 종료 시 세션 DB와 개발 기록도 정리됩니다. 실행기는 `.env.local`을 읽지 않으며, DB 연결과 새 pepper를 프로세스에만 전달합니다. 메인에서 공식 플레이 경로를 시험할 때는 이 로컬 서버에서 만든 개발 계정을 사용합니다.

## 플레이 확인

1. 경로를 선택하고 시작합니다. 앞의 초록 원까지 ↑로 이동합니다.
2. 방향키 두 개를 동시에 누른 뒤 Shift와 방향키를 함께 누릅니다. 다음 초록 원 가까이에서 E를 누르고 선택한 경로를 확인합니다.
3. 지하철은 공덕역의 오른쪽 계단 입구 표시를 지나 아래쪽 표시까지 내려갑니다. 대합실에서 E로 개찰구를 열고 중앙으로 통과합니다. 오른쪽 애오개·충정로 방면의 표시까지 걸어가 →로 탑승합니다. 충정로역 정차 안내 후 ↑로 하차합니다.
4. 버스는 260번 정류장 표시에서 E로 노선을 확인합니다. 앞문 표시로 이동해 E로 탑승합니다. STOP 표시에서 E를 누르고 정차 후 뒷문에서 E로 내립니다.
5. 완료 화면에서 목표를 확인합니다. 본 게임 준비하기는 연습한 경로를 메인에 반영합니다. 기존 로그인으로 들어간 뒤 게임 시작 버튼에서 코스를 확인합니다. 나가기는 경로 선택 없이 메인으로 돌아갑니다.
6. 방향키를 누른 채 대화 입력창을 클릭해 이동이 멈추는지 확인합니다. ESC 또는 입력창 밖 클릭 후 새로 방향키를 눌러 이동합니다. 브라우저가 포커스를 잃은 뒤에도 키를 다시 눌러야 합니다.

승하차 표시는 로컬 연습용입니다. 차량 장면 사이 전환이 실제 이동을 대신하며, 정차 대기는 2.5초이고 열린 문은 다음 조작까지 기다립니다. 실제 운행 로직을 바꾸지 않았습니다.

## 전후 비교와 브라우저 확인

개선 전 시안은 기존 폴더에서 `python3 tutorial/serve.py`로 열 수 있습니다. [이전 시안](http://127.0.0.1:8033/)과 통합본을 같은 창 크기로 열고, 지하철 개찰구나 버스 벨 단계에서 먼 위치와 근접 위치를 비교하세요.

1. 로그아웃 상태에서 메인 → 튜토리얼 → 나가기 → 메인 통과를 확인합니다.
2. 지하철 개찰구에서 멀리 있을 때 방향키 안내, 범위 안에서 E 안내, 범위 밖으로 나온 뒤 E 안내가 사라지는지 확인합니다. 계단에서 위·아래 방향과 좌우 화면 가장자리 표시를 확인합니다.
3. 지하철과 버스를 각각 완주합니다. 문 앞 영역, 벨과 개찰구의 외곽선을 비교하고 완료 직후 이전 안내가 지워지는지 확인합니다.
4. 플레이 중 대화창에 ‘어디로 가?’와 ‘뭘 눌러?’를 입력해 하단 안내와 비교합니다.
5. 본 게임 준비하기로 복귀하면 로그인 안내와 선택한 경로가 나타납니다. 로그인 후 경로가 코스 선택에 반영되지만 자동 시작되지 않아야 합니다.
6. 로그인 전에 ID 생성 화면에서 두 칸을 비워 제출합니다. 오류가 각 칸에 표시되고 닉네임 칸으로 포커스가 이동하는지 확인합니다. 10자·11자, 공백, 영문 대소문자가 다른 중복, 숫자·특수문자, 3·5자리와 문자 포함 비밀번호, 0으로 시작하는 비밀번호를 개발 계정으로 확인합니다.
7. 로그인 후 메인에서 튜토리얼 버튼이 사라지고 직접 주소도 메인으로 돌아오는지 확인합니다. 로그아웃하면 버튼이 다시 보입니다. 네트워크 오류는 개발자 도구의 오프라인으로 재현하고, 중복 오류와 달리 입력이 유지되는지 확인합니다.

## 평가 문장

| 입력 | 기대 결과 |
| --- | --- |
| 이동 방법 알려줘 / 어떻게 걸어? | 둘 다 `show_controls`의 `move` 안내를 표시합니다. |
| 어디로 가? / 뭘 눌러? / 다시 알려줘 | 현재 목표와 거리 조건에 맞는 안내를 강조합니다. |
| 개찰구가 어디야? | 개찰구 단계에서 사용 가능한 접근과 조작을 안내합니다. |
| 지금 시작할 수 있어? | `get_tutorial_status`로 현재 상태를 보여 줍니다. |
| 연습 시작해줘 / 튜토리얼 해볼래 | 경로가 없으면 실행 전에 질문합니다. |
| 버스 | 직전 질문에 대한 답이면 버스 연습을 시작합니다. 대기 요청이 없으면 경로를 선택합니다. |
| 지하철 연습 시작해줘 | 준비 화면에서 경로 질문 없이 시작합니다. |
| 버스로 바꿔줘 | 지하철 연습 중에는 BLOCK 처리합니다. |
| 처음부터 / 나가기 | 같은 경로를 초기화하거나 경로 선택 화면으로 돌아갑니다. |

경로 확인 질문에 `취소` 또는 다른 요청으로 답하면 대기 중인 시작 요청을 지웁니다. 같은 경로 시작을 반복해도 연습 세션은 초기화되지 않습니다. 기능 호출 보기의 대기 항목은 실행 결과와 구분됩니다.

## 구조와 테스트

- `dialogue.mjs`는 로컬 문장 해석과 누락값 대기를 담당합니다. `state.mjs`의 허용 목록과 상태 검사가 호출을 실행합니다. 화면 표시는 `app.mjs`, 키 상태는 `input.mjs`에 있습니다.
- 튜토리얼은 정적 리소스만 요청하며 공식 플레이·기록 API를 사용하지 않습니다. 통합 로컬 서버는 본편 API에 임시 개발 DB를 연결합니다. 일반 빌드에는 메인 진입 표시용 메타 태그와 튜토리얼 엔드포인트가 포함되지 않습니다.
- 재사용 자산은 `online-game/dist/`의 Three.js 장면, 주인공 및 NPC 리그와 모션, 공덕 거리와 260번 정류장, 공덕역 입구·개찰구 GLB, 승강장·차량 내부입니다.
- 실제 AI 연결은 제공하지 않습니다. 공급자를 연결할 때는 해석기 호출을 서버에 두고, 비밀값과 도구 권한을 서버에서 관리하세요. 본편 진입 연결 전에는 로그인 경계를 점검하고, 연습에서는 공식 플레이 및 기록 호출이 일어나지 않는지 다시 검증해야 합니다.

```bash
node tutorial/tests/tutorial.test.mjs
python3 -B tutorial/tests/server_test.py
bash tutorial/run-local.sh --test
```
